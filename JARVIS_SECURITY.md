# J.A.R.V.I.S. V2 — Security, Passcode & Privacy Architecture

## Security Principles

J.A.R.V.I.S. V2 is designed to protect user privacy, personal data, and local system integrity:
1. **Zero Cloud Telemetry:** No user queries, voice recordings, system telemetry, or personal notes are ever transmitted to third-party AI companies, analytics trackers, or remote servers.
2. **Local Sandboxing:** All memory banks, configuration files, flaw audits, and logs reside strictly on the local machine under `c:\Users\devkk\OneDrive\Documents\Jarvis\`.
3. **No Hardcoded Secrets:** Configuration files use local environment variables or template defaults. Private tokens and chat IDs are kept isolated.

---

## Passcode 2681 Authentication

Remote Telegram interactions and privileged administrative commands require authentication via the master Stark protocol passcode:
- **Passcode:** `2681`
- **Protected Operations:**
  - Remote shell command dispatch
  - Project repository archive transmission
  - Memory bank erasure
  - Workstation lockdown or shutdown
- **Verification Flow:**
  1. Incoming Telegram message is checked against `memory/authorized_telegram_chats.json`.
  2. If the chat ID is not authorized, the sender is prompted for the 4-digit passcode.
  3. Once `2681` is provided, the chat is added to authorized sessions with an encrypted timestamp.
  4. Failed attempts are logged to `memory/security_events.log`.

## Process & Subprocess Isolation

- All child processes (Piper TTS, screenshot capture, application launch) are launched with `creationflags=subprocess.CREATE_NO_WINDOW` (0x08000000) to prevent console window hijacking and flashing.
- Code generated by the Autonomous Project Builder (`skills/project_builder.py`) is verified using Python's `ast.parse()` compiler to catch syntax errors or invalid bytecodes before any execution is permitted.
- The Tactical HUD HTTP server (`core/hud_server.py`) binds exclusively to `127.0.0.1` (localhost), preventing remote access over local area networks unless explicitly tunneled.
